**Vocabulary.** *Critical*: crash, data loss, or corrupts a document. *High*: a wrong result the
user will hit, or a promise in the docs the code breaks. *Medium*: a defect with a workaround, or
a hard-invariant violation not yet reachable. *Low*: hardening, consistency, naming. *Reproduced*:
an executable example confirmed it (scripts under the session scratchpad's
`audit-2026-09-05/probes`, run with `uv run --no-sync python <script>`). *Inspected*: follows from
the current code path. *Evidence gap*: release proof is missing from the repository, not a
demonstrated failure.

**Second-look.** Every Critical and High below was re-read by the orchestrator against the working
tree. Dropped or downgraded during merge: **muse-02** (the export encode on the frame thread) came
back from its explorer as High and is recorded as Medium — it is a hard-invariant violation a user
does reach, but what it costs is a sub-second stall before a modal file picker, not a wrong result,
and *High* in this file is reserved for a wrong result or a broken promise. Three further
candidates were dropped before they became records: a cancel of a music job during checkpoint
loading is not interruptible, but that is the documented and accepted `t2i_load` pattern rather
than anything Muse-specific (`queue.py:1042,1057-1058`); `muse_results.sync`'s full-cache scan
measured 0.55 ms at 5000 jobs and the code already reasons about that cost; and `separate_job`
minting rows without a `stage=` is not a Muse defect (`rig_job` does the same).

**What the fix phase found that the report had not.** Two records were narrower than the defect
behind them, which is worth recording because it is the audit's own error, not the fixers':

- **muse-05 named two export prefixes; there are six.** The fixer's sweep found `muse-export:`,
  `sirens-export:`, `clay-export:`, `inker-export:`, `packwright-export:` and `plotter-export:`,
  none of them matched by the quit guard. The audit read the two the explorer happened to open.
- **muse-01's grid was worse than "no audio button".** A music job did not merely lack the three
  audio rows; it fell through `artifacts_for` to the *mesh* tuple, so a finished take offered
  `model.glb`, `model.fbx` and six more, every one permanently blocked.

And one correction inside the fix phase itself: the first attempt at **muse-03** moved the blend
off the frame thread but left the task writing the cache's key and buffer as two statements, so a
newer Play landing between them paired one key with another's buffer — the wrong crossfade, both
audibly and in what `export_loop` then wrote. That was caught on review of the fixer's own flagged
departure, reopened, and closed properly; see INVARIANTS, "The loop cache has exactly one writer".
