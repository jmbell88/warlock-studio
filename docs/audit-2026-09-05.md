# Warlock Studio audit — 2026-09-05

**Recommendation:** close the two Highs before the next installer build — one leaks GPU
memory on every failed mesh import, the other makes the viewport lie about a finished
remesh or re-texture.

**11 findings: 0 Critical, 2 High, 5 Medium, 4 Low; 0 human-only.**

Audited: version **0.0.36**, working tree at **`85f045e3`**. Dirty at start: `clean`.
Scope: `create` → slices `create-brief`, `create-viewer`, `create-panes`, `create-logic`
(the `create` row of `references/subsystems.md`, split four ways for depth).
`uv run ruff check .`: `All checks passed!`. The suite was not run by this audit; findings
are from reading and from the offline probes below.

**Vocabulary.** *Critical*: crash, data loss, or corrupts a document. *High*: a wrong
result the user will hit, or a promise in the docs the code breaks. *Medium*: a defect
with a workaround, or a hard-invariant violation not yet reachable. *Low*: hardening,
consistency, naming. *Reproduced*: an executable example confirmed it (scripts under the
session scratchpad, `audit-2026-09-05/probes/`, run with `uv run --no-sync python
<script>`). *Inspected*: follows from the current code path. *Evidence gap*: release
proof is missing from the repository, not a demonstrated failure.

**Second-look.** Every High below was re-read by the orchestrator against the working
tree, and all four probes were re-run here. Merged during the merge: the viewer
explorer's two records were one unbounded index in one function seen from two call
sites, and are now **create-01** with two regression tests. Downgraded: the Make 3D
tooltip Medium → Low (the refusal text *is* on screen in red above the button; only the
hover tooltip misleads), and the pose Apply button Medium → Low (it greys only for the
moment the pose is applying). Dropped: none. One candidate the viewer explorer excluded
itself and I did not restore — `Model.joint_palette`'s unguarded `np.linalg.inv` —
because every reachable call site already degrades to a toast.
