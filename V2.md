/cl# Warlock Studio V2 — Python/PyGame-CE/ModernGL Conversion Plan

## Context

Warlock Studio is currently a FastAPI server with a browser frontend (`src/warlock/static/index.html` 1094 lines, `app.js` 3621 lines, vendored three.js r170). V2 converts it into a **single-process desktop app**: PyGame-CE window, **imgui-bundle** UI rendered through the same **ModernGL** context as the 3D viewport, **no JS, no HTTP, no browser**. The backend core (Worker/queue, JobStore, ProgressBus, all pipelines) is already HTTP-agnostic and survives unchanged; the ~700 lines of business logic inside `app.py` route handlers move into a service layer; the three.js viewer is rewritten as a ModernGL renderer. The app must behave identically to today.

User decisions (confirmed): single-process (no FastAPI at the end), imgui-bundle for widgets, the JS frontend is deleted in the final phase after parity is verified.

New dependencies (new `studio` extra in `pyproject.toml`): `moderngl>=5.10`, `pygame-ce>=2.5`, `imgui-bundle>=1.6`. **No math library** — a hand-rolled `math3d.py` on numpy (column-major glTF conventions, quaternion XYZW throughout, under our own tests; avoids pyrr convention ambiguity). `fastapi`/`uvicorn`/`python-multipart` removed at the end (`httpx` stays only if `pipelines/trellis.py` uses it for the trellis-server subprocess protocol — verify by grep before removing).

## Non-negotiable parity contracts

These are the load-bearing behaviors the rewrite must preserve exactly (from CLAUDE.md + code):

1. **Pose contract**: bone-local quaternions, **XYZW** (three.js order) on the wire to the Blender worker; `mirrorQuaternion = [x,-y,-z,w]` — the new `pose.py` **imports `rigging.mirror_quaternion`** instead of copying it (finally removing the JS-copy hazard noted at `rigging.py:351`). Joint drag deltas convert glTF→Blender as `[x,-z,y]` (deltas only, never absolutes). `corrected_bones()` keeps the tail-follows-first-child rule (`app.js:2884`). `tests/test_rigging.py`'s pose round-trip pin stays green.
2. **Single sqlite connection + RLock** (`db.py`) untouched; UI thread may read JobStore directly (it's thread-safe), partial params writes still go through `merge_params`.
3. **Fully offline** — no new runtime network calls; `HF_HUB_OFFLINE=1` stays first in `__init__.py`.
4. **VRAM modes, worker dispatch, artifact ordering** (`source.glb`→optimize→`normalize_glb`→`model.glb`), `DERIVED_PARAMS` strip on rerun/promotion, `_attach_files` gating (`model.glb` only when done; `rig.glb` only when `rig.json` exists), input caps at the door (20 MB upload, 16 MP, `MAX_PROMPT` 1000, seeds 0..2³¹−1), input.png-written-before-DB-insert + rmtree compensation — all preserved verbatim in the service layer.
5. **Blender never in-process**; rig temps/finalize ordering, poses-as-files, sheet grid planned on host — untouched.
6. Rendering parity: three r170's exact color pipeline (Stephen Hill ACES fit, sRGB OETF, exposure 1.0), the procedural gradient environment with its **load-bearing ambient-from-below**, same lights, same camera framing math, same sheet-preview camera math (yaw 0 on +Z).

## Architecture

### Process model & threading

| Thread | Runs | Blocking allowed |
|---|---|---|
| **Main (pygame)** | event pump, imgui build, viewer render, direct `JobStore` reads, `worker.progress.snapshot()` | No (~16 ms budget) |
| **Loop thread** (`warlock-loop`) | asyncio loop (`run_forever`) hosting `Worker` | asyncio-only |
| **TaskRunner pool** (`ThreadPoolExecutor(4)`) | blocking service calls from UI: artifact derivation, exports, `_to_png`, prune/delete, Blender pose bakes, tokenizer | Yes |

- `Runtime.start()` reimplements the FastAPI lifespan (`app.py:124-143`): `get_config` → `JobStore` → `reconcile_startup` → `doctor.run_checks` → start loop thread → `Worker(config, store)` started **on the loop** via `run_coroutine_threadsafe` → `WarlockService(config, store, worker, loop)`.
- `wake_worker()` = `loop.call_soon_threadsafe(worker.wake)` (wake is loop-affine per `queue.py:142-150`). Cancel = `run_coroutine_threadsafe(worker.request_cancel(...))` then the `store.cancel` race handling from `app.py:581`, all inside a TaskRunner task.
- **`_convert_locks` become `threading.Lock`s** (table on `WarlockService`, get-or-create under a meta-lock). Justification: every caller is now a plain thread (TaskRunner), the protected work is blocking anyway (Blender ~1 s, trimesh exports), and this keeps 1-second bakes off the loop that drives dispatch/cancel. Rule enforced: derive/optimize/bake service functions never run on the main thread (debug assert on thread name).
- Progress: **no polling protocol at all** — the frame loop calls `worker.progress.snapshot(job_id)` directly. Percent easing (creep) is computed inside snapshot, so per-frame calls give smoother bars than the browser ever had.
- Shutdown: `worker.shutdown()` on the loop (30 s timeout) → stop loop → join → executor shutdown → `store.close()`.

### Service layer (extract-under-the-routes)

Extraction happens **while `app.py` still exists**: each route body becomes `try: return svc.xxx(...) except ServiceError as e: raise _to_http(e)`. The existing TestClient suites (`test_api.py` 1473 lines, `test_poses_api.py`, `test_rig_api.py`, `test_sheet.py`) stay green throughout and act as the parity harness. `app.py` is deleted only in the final phase.

Exception hierarchy (mechanical mapping from HTTPException): `NotFound`(404), `Invalid`(400/422, carries field), `Conflict`(409), `NotReady`(artifact gating), `TooLarge`(413), `Unavailable`(503). UI catches `ServiceError` at the TaskRunner boundary and toasts `exc.message`.

## Viewer design (ModernGL, replacing three.js)

**No custom shaders exist in the JS** — parity means reimplementing three r170's *stock* pipeline. Verified GLB facts: no KHR extensions, float32/uint32 attributes, single primitive, pbrMetallicRoughness with baseColor (sRGB) + metallicRoughness (linear, G=rough B=metal), transform **not baked** (root `{}` → child `{scale,translation,mesh}`), rig.glb has a 20-joint skin (JOINTS_0 uint8, WEIGHTS_0 f32, IBM mat4, synthetic `neutral_bone` is a real joint), 443k verts / 882k uint32 indices.

Key decisions:
- **GLB loader: hand-rolled** (`viewer/gltf.py`, ~250 lines on numpy + Pillow, reusing `glbio.py`). trimesh discards root transforms and has no skinning; pygltflib still leaves accessor decoding to us. Zero new deps, fully testable against real assets.
- **Skinning: `uniform mat4 u_joints[64]`** vertex-shader LBS (GL 3.3 guarantees 256 mat4 of uniform space; 20 joints is nothing). JOINTS_0 promoted uint8→int32, bound as `ivec4`.
- **Color pipeline**: shade linear → **Stephen Hill ACES fit** (with the 1/0.6 pre-scale — omitting it is the classic "everything is dark" bug) → exact piecewise sRGB OETF, at the end of every lit/unlit fragment shader; render into **RGBA8 4×MSAA FBO per viewport**, resolve-blit, display via `imgui.image` (UV-flipped). Background `0x14151a` run through the same transform on CPU once and used as the clear color.
- **IBL**: build the 32×16 half-float gradient equirect in numpy (sky [0.42,0.48,0.60], horizon [0.34,0.34,0.36], ground [0.16,0.155,0.15]); **diffuse = SH9 projected on CPU** (exact for a smooth gradient; carries the ambient-from-below), **specular = GGX importance-sampled 64² cubemap, 7 mips** (roughness=mip/6, ~42 tiny startup draws), **env BRDF = the Lazarov/Karis `DFGApprox` polynomial** — which is what three r170 itself uses, so we match by construction. Full PMREM port rejected (no visual payoff on a gradient).
- **Lights**: hemisphere (0xffffff/0x000223, 0.3) via three's `getHemisphereLightIrradiance` math + directional (white, 1.5, from (3,4,2)), world-space, no shadows. BRDF: Lambert + GGX/Smith height-correlated + Schlick, `F0 = mix(0.04, albedo, metallic)`.
- **Programs** (`#version 330 core`): `pbr` (defines: SKINNED/HAS_UV/HAS_MR_MAP/HAS_NORMAL_MAP/HAS_EMISSIVE/HAS_AO — normal/emissive/AO supported defensively per `postprocess._TEXTURE_SLOTS`), `unlit` (flat sheet mode; keeps ACES since MeshBasicMaterial default `toneMapped=true`), `lines` (grid; MSAA is the AA, same as three), `solid` (markers/gizmos; markers drawn last with depth off = renderOrder 999), `prefilter` (startup only). Wireframe via `ctx.wireframe = True` (desktop-only app; comment why so nobody "fixes" it for GLES).
- **Camera/controls** (`camera.py`): fov 45; `frame()` = exact JS math (`d = r/sin(fov/2)·1.25`, pos `(0.62d, 0.47d, 0.62d)`, target `(0, sy/2, 0)`, near `r/1000`, far `r·100`); OrbitControls with damping `(1-0.05)^(dt·60)`, distance clamp `r·0.5..r·20`, pan scaled by `distance·tan(fov/2)/viewport_h`, wheel dolly, turntable (S).
- **Picking**: analytic `screen_ray` + **ray-sphere is sufficient** for joint markers (constant world radius `r·0.022`, depth off) — no GPU ID buffer anywhere.
- **Gizmos** (`gizmo.py`, hand-rolled TransformControls subset): RotateGizmo (3 line-loop rings, local space, constant screen size ·0.6, ring-band hit test, `atan2`-angle drags → quat delta post-multiplied onto the bone's local rotation) and TranslateGizmo (3 arrows, closest-point-segment hit, axis-constrained drags) attached to markers in joints mode. Coordinate conversion lives in `pose.py`, gizmos stay agnostic.
- **Compare view**: second `Viewport` (FBO pair) whose camera copies the primary each frame — one GL context, shares everything (simpler than the JS two-renderer setup).
- **Sheet preview** (`viewer/sheet.py`): 64×64 FBO per yaw, ortho camera `extent = max(hypot(sx,sz), sy)·1.12`, distance `extent·2`, yaw 0 on +Z, elevation slider, alpha-0 clear, flat mode = unlit-textured swap; readback → row-flip → Pillow strip composite. One shared `read_fbo_image(fbo) -> Image` in `capture.py` used by sheet, screenshot, thumbnail, and regression tests.
- **Thumbnail/screenshot**: FBO readback → PNG; thumbnail handed to `service.files.save_thumbnail` (replaces POST /thumb.png).
- **imgui interop**: one GL context; viewports are resolved textures shown as `imgui.image`; viewer input fires only when the image item is hovered (coords remapped item-local), drags keep ownership until button-up; keyboard gated on `io.want_capture_keyboard`. If imgui-bundle's pygame backend proves rough, fall back to feeding `io` manually from pygame events (~80 lines) — do not switch windowing libs.

- imgui-bundle pygame backend maturity — fallback is manual `io` feeding (~80 lines), not a windowing-lib switch (V3).
- `httpx` removal — only if pipelines don't use it (D2 grep).
